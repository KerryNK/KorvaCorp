# Korva Global Corporation

Django serves the existing single-page Korva Global website, its original assets, and a database-backed contact inquiry form. The page's original inline CSS, JavaScript, content, and layout remain intact.

## Local setup

1. Create and activate a virtual environment.
2. Install dependencies with `pip install -r requirements.txt`.
3. Copy `.env.example` to `.env`. For local development, set `DJANGO_DEBUG=True`; change the secret key before deployment.
4. Initialize the database with `python manage.py migrate`.
5. Start the development server with `python manage.py runserver` and open `http://127.0.0.1:8000/`.

## Admin and inquiries

Create an administrator with `python manage.py createsuperuser`, then sign in at `/admin/`. Contact form submissions are stored as `ContactSubmission` records and can be searched and filtered from the admin.

## Project map

- `index.html` is the original landing page, rendered through Django's template engine. It remains at the project root so its large self-contained design is not restructured.
- `config/` contains Django settings, URL configuration, and ASGI/WSGI entry points.
- `core/` contains the homepage view, form, submission model, admin registration, tests, and error templates.
- `Assets/` contains the original logo and background video and is configured as a Django static-files source. Their public URLs are served under `/static/`.
- `staticfiles/` is generated by `collectstatic`; it should be served by the production web server or CDN.

## Add a page

Add a view in `core/views.py`, a route in `core/urls.py`, and a template. The existing landing page intentionally stays self-contained to avoid changing its original DOM or behavior; use `core/templates/core/base.html` as the base for new non-landing pages.

## Production deployment

- Set `DJANGO_DEBUG=False`, a unique `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, and `DJANGO_CSRF_TRUSTED_ORIGINS` in the deployment environment.
- Enable `DJANGO_SECURE_SSL_REDIRECT` and `DJANGO_SECURE_COOKIES` when HTTPS is configured at the application or trusted proxy layer. After confirming HTTPS is permanent, set `DJANGO_SECURE_HSTS_SECONDS` (for example, `31536000`). Enable `DJANGO_SECURE_HSTS_INCLUDE_SUBDOMAINS` or `DJANGO_SECURE_HSTS_PRELOAD` only after confirming their additional domain-wide implications.
- Install dependencies, run `python manage.py migrate`, then `python manage.py collectstatic --noinput`.
- Serve the WSGI application with Gunicorn: `gunicorn config.wsgi:application` (or use an ASGI server with `config.asgi:application`). Serve the generated `staticfiles/` directory from the web server/CDN. Back up the database and protect admin access in the deployment environment.
- Run `python manage.py check --deploy` before release and configure HTTPS, backups, logging, and monitored error reporting at the hosting layer.

## Validation

Run `python manage.py test` for homepage, contact validation, persistence, and honeypot coverage. Run `python manage.py makemigrations --check --dry-run` to confirm model changes have corresponding migrations.
